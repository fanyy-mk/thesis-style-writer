# 中文学位论文的 AI 腔清单

## 0. 先定义

“AI 味”不是某个词本身，而是四种缺席：

| 缺席 | 表现 | 读者感受 |
| --- | --- | --- |
| 处境 | 任何题目都能套的开场与结论 | 换掉关键词仍是同一篇 |
| 取舍 | 只讲方案好，不讲为什么不用别的 | 像产品介绍，不像研究 |
| 颗粒度 | 没有数字、版本、参数、失败案例 | 说了很多，什么也没说 |
| 节奏 | 句子、段落、句数都差不多长 | 像匀速朗读 |

因此，去 AI 味的目标是**具体、有取舍、节奏自然的学术中文**，不是绕过某个检测器。检测器只是代理指标，不能代替作者核对事实。

## 1. A 级：硬禁（0 容忍）

脚本命中即阻断。不是这些词绝对不能用，而是它们在没有具体信息时几乎总是废话。

| 类别 | 典型表达 | 为什么假 | 改法 |
| --- | --- | --- | --- |
| 宏大开场 | 随着信息技术的飞速发展…… | 任何题目都能套 | 用时间、地点、数字或事件开头 |
| 时代背景 | 在当今数字化时代…… | 没有信息量 | 直接写研究对象与约束 |
| 伪共识 | 众所周知、毋庸置疑、显而易见、不可否认 | 把个人判断说成共识 | 删；需要共识就给引用 |
| 意义套话 | 具有重要的理论意义和实践意义 | 不说明解决了什么 | 写具体贡献与指标变化 |
| 价值套话 | 提供新思路、有益参考、奠定坚实基础 | 评价先于证据 | 写可复用的方法、参数或流程 |
| 前景套话 | 广阔应用前景、注入新活力、保驾护航、开启新篇章 | 宣传语 | 删 |
| 程度空转 | 极大地、有效地提升、完美解决 | 无基线、无数值 | 给前后值、测试条件与样本量 |
| 管理黑话 | 赋能、抓手、闭环、多维度、全方位、进一步地、深入地、全面地 | 换词不增量 | 写具体动作与对象 |
| 对偶排比 | 不仅是……更是……、既……又…… | 修辞替代论证 | 拆成两个事实句 |
| 万能功能 | 发挥着重要作用、起到了……作用 | 不说机制 | 写输入、处理、输出与失败后果 |
| 绝对化 | 完美、彻底、完全解决 | 忽略边界 | 给适用条件与残余问题 |
| 口语 | 说白了、其实吧、大家都知道 | 语体不符 | 改为有条件陈述 |

## 2. B 级：配额（少量可用）

配额是**每千字上限**，短稿至少允许 1–2 次；以 `ai_check.py` 报告为准。超过上限两倍即阻断。

| 表达 | 参考上限/千字 | 使用条件 |
| --- | --- | --- |
| 此外 | 1.5 | 真正并列，且后句有新信息 |
| 同时 | 1.5 | 时间同时或机制并行，不用于硬接观点 |
| 然而 | 1.2 | 真转折，前后必须对立 |
| 因此 | 2.0 | 因果成立，后句可由前句推出 |
| 综上所述 | 0.4 | 仅章末，全文不超过 2 次 |
| 值得注意的是 | 0.4 | 后面确实有反直觉信息，否则删前缀 |
| 由此可见 | 0.4 | 改为直接写推论链 |
| 在一定程度上 | 0.5 | 限定要具体到条件或范围 |
| 一方面/另一方面 | 0.5 | 两面都落到机制，不写空评价 |
| 不仅……而且 | 0.6 | 拆成两个事实句通常更好 |
| 本文 | 2.5 | 不要每段都以“本文”开头 |
| 我们 | 2.0 | 按画像；中文学位论文多用“本文/笔者” |
| 首先/其次/再次/最后 | 0.3–0.5 | 同一段出现两个以上直接判机械枚举 |
| 使得 | 1.0 | 确认因果，不用于弱相关 |
| 在……方面 | 0.8 | 改为以对象作主语 |
| 构建……体系 | 0.8 | 写清体系由哪些模块组成 |

## 3. C 级：结构（节奏与模板）

### 句长过匀

标准差低于 8（20 句以上）即阻断。典型 AI 草稿每句 25–35 字，读起来像节拍器。改法不是把每句改短，而是**保留中等句，插入少量 12–18 字短句和少量 50 字以上长句**。

### 段落等长

段长 CV 低于 0.13（6 段以上）即阻断。人写论文会有一段只写两句，也会有一段铺 300 字。检查方法：如果每段都 3–5 句、长度 100–140 字，基本是模板。

### 每段句数相同

每段句数标准差低于 0.6（5 段以上）要告警。不要用“每段四句”这种结构写整章。

### 段首连接词过多

超过 25% 的句子以“因此/所以/同时/此外/总之”开头，说明过渡靠连接词而不是内容。删掉一半，用名词回指或顺序表达。

### 三元并列

“稳定性、安全性与可扩展性”这类三项排比，是 AI 最稳定的指纹之一。改成两项并说明差异，或让三项分别承担不同信息（一项是约束、一项是代价、一项是收益）。

### 破折号解释

“——也就是说……”多数可直接删。全文破折号越少越好。

### 正文列表化

学位论文正文用段落论证，不用“1. 2. 3.”或项目符号。列表只适合参数表、步骤清单或附录。

### 章节模板

每章都以“本章主要介绍了……”开头，是最明显的模板。直接进入问题、约束或结论；需要导览时放在章末一段，且不要每章同句式。

### 句首重复

连续多句以同一个四字短语开头（尤其“本文认为”“该系统”）会显得机械。换主语：研究对象、数据、模块、操作者。

### 重复四字片段

脚本会统计重复四字片段占比。术语重复是正常的，非术语片段反复出现才是问题。

## 4. D 级：内容（最容易被脚本漏掉）

### 泛化引用

“研究表明，该方法效果更好。”——谁的研究？在什么数据上？好在多少？改为：“文献[5]在 40 万条日志上测得召回率 0.88，单条耗时 5.6 ms。”

### 程度词无数据

“显著提升”“大幅改善”“明显优于”必须同句给出基线、数值或条件，否则删掉程度词，或补实验。

### 长段无具体信息

90 字以上的段落没有任何数字、版本、参数、文献编号或英文术语，通常说明这段在空转。至少补一个可核查的物。

### 没有取舍

每章至少两处说明“为什么不用另一种方案”。没有取舍的设计章，读起来像说明书。

### 没有失败与局限

只报最好结果、不提失败样本和适用边界，是典型生成文本特征。写清哪类样本会漏、哪个条件会退化、代价是什么。

### 正确的废话

“系统设计应遵循科学性、合理性、可扩展性原则。”——删。原则不能指导实现，接口、字段、阈值才能。

### 术语漂移

同一概念在“检测系统/检测平台/检测框架”之间轮换，是模型为避免重复而做的同义替换。锁定一个术语，写进画像的术语表。

### 结论复读摘要

结论章重复摘要的句子，没有新增信息。结论只写：做了什么、得到什么、还差什么。

## 5. 这些做法不算去 AI 味

| 做法 | 为什么无效/有害 |
| --- | --- |
| 同义词替换（此外→另外） | 模板结构没变，仍然匀 |
| 把每句都拆短 | 变成另一种机械节奏 |
| 故意加口语、错别字 | 学位论文语体不合格 |
| 加“笔者认为”但不给观点 | 只增加了人称，没有增加判断 |
| 编造数据或文献 | 学术不端，且经不起核对 |
| 删掉所有连接词 | 逻辑断裂，读不懂 |
| 用破折号、比喻装个性 | 只是换了一种 AI 腔 |
| 为凑段落差异加填充句 | 段落变长但没有信息 |

## 6. 改写手术（按顺序做）

1. **删评价，留事实**
   - 前：该系统具有重要的实用价值。
   - 后：系统上线后，值班员日均处理告警从 46 条降到 12 条。
2. **用事件/数据开场**
   - 前：随着网络安全形势日益严峻，……
   - 后：2025 年 3 月至 5 月，出口日志记录了 12,438 次 SSH 登录失败，其中 63% 集中在 22 端口。
3. **给取舍**
   - 前：系统采用模块化设计，具有良好的可扩展性。
   - 后：采集端与分析端拆成两个进程，代价是多一次消息队列转发（约 80 ms），换来分析模块可以单独重启。
4. **给限定**
   - 前：该方法准确率高。
   - 后：在本次样本内（n=1,204,881）精确率为 0.91；换到教师住宅 VPN 流量时降到 0.72。
5. **拆长句**
   - 前：在校园网规模不断扩大、攻击手段不断演进的背景下，传统基于阈值的检测方法难以兼顾准确率与性能，因此需要引入新的方法。
   - 后：校园网出口日志已从日均 12 万条增至 45 万条。阈值法在这个量级下仍能跑，但误报随白名单膨胀而上升。引入序列模型，是为了补上低速攻击的漏报。
6. **并短句**
   - 前：系统采用旁路部署。系统不参与认证。系统故障不影响登录。
   - 后：系统采用旁路部署，不参与认证流程；检测服务故障时只会丢弃日志，不会阻塞 SSH 登录。
7. **换主语**
   - 前：本文对日志进行了分析。
   - 后：日志按源地址聚合后只剩 6 个字段，单条体积从 1.8 KB 降到 240 B。
8. **动词化**
   - 前：对系统进行了性能测试。
   - 后：压测覆盖 1,900 条/秒的峰值，连续运行 6 小时。
9. **引用具体化**
   - 前：研究表明，会话模型效果更好。
   - 后：文献[5]在 40 万条日志上测得会话模型召回率 0.88，代价是单条推理 5.6 ms。
10. **调序：先结论后依据**
    - 前：因为 A，所以 B，但 C，因此 D。
    - 后：D 成立的前提是 C。A 在 B 条件下满足；超出这个条件，结论不成立。

## 7. 判定顺序

1. **先看内容**：这段有没有一个可核查的信息、一个取舍、一个限制？
2. **再看结构**：句长、段长、句数、段首是否过匀？
3. **最后清词**：A 级删，B 级压到配额内。

顺序不能反。先改词，会把一段空话打磨得更顺，反而更难发现问题。

## 8. 一句话标准

改完之后，把这段单独拿给同专业同学看：他应该能说出你用了什么数据、做了什么取舍、哪里可能失败。如果只能说出“写得挺顺”，就还没过关。
